## 🎯 시스템 개요

이 시스템은 **RFP(Request for Proposal, 제안요청서)**를 입력받아 LLM과 외부 검색 API를 활용하여 자동으로 제안서를 생성하는 Streamlit 기반 웹 애플리케이션입니다.

### 주요 기능
- **RFP 업로드 및 분석**: PDF/DOCX/TXT 파일에서 텍스트 추출
- **자동 제안서 생성**: LLM을 활용한 요청사항 분석 → 리서치 → 제안방안 생성 → 슬라이드 설계
- **옵션 선택 및 미리보기**: 요청별로 여러 제안 옵션 중 선택하여 미리보기
- **다양한 형식 내보내기**: PDF, Excel, PPT 형식으로 제안서 다운로드
- **고객/프로젝트 히스토리 관리**: SQLite 기반 데이터베이스로 이력 관리

### 2. **pipeline/rfp2proposal.py** - 핵심 파이프라인

**역할**: RFP 텍스트를 제안서 DataFrame으로 변환하는 전체 파이프라인

**주요 단계**:

#### Step 1: RFP 텍스트 추출
```python
extract_text_from_file(rfp_path)
```
- PDF, DOCX, TXT 파일에서 텍스트 추출
- 후처리: 줄바꿈 정리, 공백 정규화

#### Step 2: 요청사항/제안방안/질문 생성
```python
rfp_requirement_check(user_inputs, conf)
parse_rfp_response_to_dict(lines)
```
- **입력**: RFP 텍스트, 고객 방향성
- **출력**: 요청사항별로 구조화된 딕셔너리
  ```python
  {
    "요청사항_0": {
      "제안요청사항": "...",
      "제안방안": "...",
      "실현질문": ["질문1", "질문2"],
      "벤치마킹질문": ["질문1", "질문2"]
    },
    ...
  }
  ```

#### Step 3: 외부 리서치 (Perplexity/SerpAPI)
```python
generate_answer_dict(rfp_dict, prefer="perplexity", logf=logf)
```
- 각 질문에 대해 외부 검색 수행
- **Perplexity API**: 기본 사용 (sonar-pro 모델)
- **SerpAPI**: 폴백 옵션
- **출력**: 질문별 답변 텍스트 + 인용 URL 리스트

#### Step 4: 업데이트된 제안방안 생성
```python
generate_updated_plans_per_question(rfp_dict, answer, rfp_text, conf, logf)
```
- 리서치 결과를 바탕으로 기존 제안방안을 개선
- **실현질문**: 모든 Q/A를 통합하여 하나의 업데이트된 제안방안 생성
- **벤치마킹질문**: 각 질문별로 개별 업데이트된 제안방안 생성
- **출력**: DataFrame
  ```python
  columns: ["요청 ID", "제안요청사항", "질문유형", "질문", "답변", "urls", "updated_제안방안"]
  ```

#### Step 5: 슬라이드 흐름 설계
```python
_slim_from_updated_df(updated_df, model, logf, collect_sections)
```
- 각 요청사항별로 4개의 옵션 시드를 생성
- OpenAI Responses API를 사용하여 각 옵션별 슬라이드 흐름 설계
- **출력 구조**:
  ```json
  {
    "req_id": "요청사항_0",
    "req_title": "...",
    "overview_slide": {...},
    "options": [
      {
        "option_no": 1,
        "option_title": "...",
        "why_choose": [...],
        "fit_signals": [...],
        "risks": [...],
        "mitigations": [...],
        "timeline": [...],
        "slides": [
          {
            "slide_no": 1,
            "title": "...",
            "subtitle": "...",
            "content_draft": "...",
            "urls": [...]
          },
          ...
        ]
      },
      ...
    ]
  }
  ```

#### Step 6: DataFrame 변환
```python
build_flows_from_user_inputs(...) → pd.DataFrame
```
- JSON 구조를 앱에서 사용하는 DataFrame 형식으로 변환
- **컬럼 구조**:
  - `요청 ID`, `요청 제목`
  - `옵션번호` (1, 2, 3, 4 또는 "OVERVIEW", "META")
  - `슬라이드번호` (숫자 또는 "OVERVIEW", "META", "COVER", "CLOSING")
  - `제목`, `부제목`, `본문초안`
  - `왜_이_옵션`, `적합_시그널`, `리스크`, `완화책`
  - `타임라인` (JSON 문자열)
  - `URL` (줄바꿈으로 구분된 URL 리스트)
  - `옵션대제목`

## 🔄 핵심 파이프라인 상세

### build_flows_from_user_inputs() 함수 흐름

```python
def build_flows_from_user_inputs(
    rfp_path: str,
    client_name: str,
    user_direction: str,
    notes: str = "",
    model_main: str = "gpt-5",
    model_deck: str = "gpt-5",
    out_dir: Optional[str] = None,
    logf: Optional[Callable] = None
) -> pd.DataFrame:
```

**실행 순서**:

1. **텍스트 추출** (5%)
   ```python
   rfp_text = extract_text_from_file(rfp_path)
   ```

2. **요청/질문 생성** (15%)
   ```python
   req_lines = rfp_requirement_check(user_inputs, OpenAIConf(...))
   rfp_dict_raw = parse_rfp_response_to_dict(req_lines)
   rfp_dict = _cap_rfp_dict(rfp_dict_raw)  # 상한 적용 (최대 4개 요청)
   ```

3. **리서치** (35%)
   ```python
   answers = generate_answer_dict(rfp_dict, prefer="perplexity", logf=logf)
   # 각 질문마다 Perplexity API 호출
   ```

4. **업데이트된 제안방안 생성** (20%)
   ```python
   updated_df = generate_updated_plans_per_question(
       rfp_dict, answers, rfp_text, OpenAIConf(...), logf=logf
   )
   # 실현질문: 통합, 벤치마킹질문: 개별
   ```

5. **슬라이드 흐름 설계** (20%)
   ```python
   sections = []
   df = _slim_from_updated_df(
       updated_df, 
       model=model_deck, 
       logf=logf, 
       collect_sections=sections
   )
   # 각 요청별로 4개 옵션 시드 → Responses API로 슬라이드 설계
   ```

6. **저장** (5%)
   ```python
   master = _make_master_from_sections(sections)
   # JSON 및 Excel 파일 저장
   ```

## 🔑 핵심 개념

### 1. 요청 ID (Request ID)
- 각 RFP에서 추출된 제안 요청사항을 구분하는 식별자
- 형식: `요청사항_0`, `요청사항_1`, ...
- 최대 4개까지 처리 (환경변수 `RFP_MAX_REQS`로 조정 가능)

### 2. 옵션번호 (Option Number)
- 각 요청사항별로 생성되는 제안 옵션을 구분
- 일반 옵션: `"1"`, `"2"`, `"3"`, `"4"`
- 특수 옵션:
  - `"OVERVIEW"`: 요청별 옵션 비교 개요 슬라이드
  - `"META"`: 옵션의 메타 정보 (왜 이 옵션, 리스크 등)

### 3. 슬라이드번호 (Slide Number)
- 각 옵션 내의 슬라이드를 구분
- 일반 슬라이드: `"1"`, `"2"`, `"3"`, ...
- 특수 슬라이드:
  - `"COVER"`: 표지
  - `"OVERVIEW"`: 옵션 비교 개요
  - `"META"`: 옵션 메타 정보
  - `"CLOSING"`: 마무리

### 4. 슬림 플로우 (Slim Flow)
- 최종 출력되는 DataFrame의 구조
- 각 행은 하나의 슬라이드를 나타냄
- 요청 ID → 옵션번호 → 슬라이드번호 계층 구조

### 설정 파일
- `.streamlit/secrets.toml`: API 키 및 인증 정보
  ```toml
  OPENAI_API_KEY = "sk-..."
  PERPLEXITY_API_KEY = "pplx-..."
  
  [auth]
  enabled = true
  
  [auth.users]
  admin = "sha256:..."
  ```

### 환경변수 (선택)
- `RFP_MAX_REQS`: 최대 요청사항 개수 (기본: 4)
- `RFP_MAX_Q_REALIZE`: 요청별 실현질문 최대 개수 (기본: 2)
- `RFP_MAX_Q_BENCH`: 요청별 벤치마킹질문 최대 개수 (기본: 1)
- `FILE_DATE_SUFFIX`: 파일명 날짜 접미사 (기본: 오늘 날짜)
